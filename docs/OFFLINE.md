# Offline mode: how it works and what it can't do
**Status:** implemented and covered by automated tests (engine, IndexedDB store, real-app offline cycle against a fake Supabase). **Not yet verified in real browsers or on a phone.**
- **App files:** the service worker (`sw.js`) caches the site shell after the first visit, so ShinkaLife opens without internet (shows `offline.html` only if the shell isn't cached yet).
- **Your data:** while online, a copy of your quests, categories, reminders, events, schedule blocks (next 60 days), available hours, settings, XP and saved assistant messages is kept on this device (IndexedDB, per account). Offline, pages read that copy.
- **Changes you can make offline:** add/edit/complete/delete quests, steps and categories; add/snooze/dismiss/edit/delete reminders; assistant name and reminder settings. They are queued with client-generated ids and replayed in order when you're back online, so retries can't create duplicates. XP for quests completed offline is awarded by the server function when synced (never by the browser).
- **Needs internet:** sign-in/up, AI answers, approving schedules, calendar events and time blocks, available hours, profile changes, weekly reflections, saved assistant history. These say so instead of failing silently.
- **Conflicts:** if a quest was changed on another device after you edited it offline, your offline edit is NOT applied. Settings > Offline & sync shows it with "Apply my change anyway" / "Keep the other version". Reminders and settings use last-write-wins.
- **Status indicator:** a pill at the top shows Online / Offline / Syncing / Needs attention, with the number of waiting changes. Failed items (refused by the server, e.g. by a rule) are listed with their reason and can be retried or discarded.
- **Sign-out:** if changes are unsynced you are asked first; signing out wipes this device's copy. Closing the browser or clearing site data **while changes are waiting loses them**: sync before clearing.
- **Offline start:** if you open the app offline and your login can't be confirmed, it uses the saved copy in read/queue mode with a banner, and asks you to sign in again when online. (Written and unit-tested around the auth events, but depends on how each browser's Supabase session behaves offline: verify on your devices.)
- **Browser limits:** private/incognito windows may block IndexedDB (the app then keeps changes only for that tab and says so); iOS Safari can purge site data after weeks of non-use; Firefox desktop can't install the app but works offline in a tab. The AI never answers offline: the local rule-based assistant does, labelled "Rule-based", and AI resumes when you're back online.
